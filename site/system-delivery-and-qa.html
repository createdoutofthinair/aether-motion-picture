Watermark-free delivery and quality checks

On this pageRefresh the original resultDownload and validate the local fileHandoff recordObserved delivery and reusable QA boundary

Refresh the original result

Before downloading, refresh each completed task through the pinned CLI query_tasks command. Select the same work index stored in the result ledger, verify task and work status are completed, and confirm the work is a video. Use only that work’s urlWithoutWatermark or url_without_watermark field when the job is authorized for watermark-free delivery. Do not substitute url, a cover URL, or a different work index if the watermark-free field is absent.

The refreshed result URL is signed and may expire. Keep it in the requested restricted download ledger for operational recovery; do not print it to a terminal, chat, report, screenshot, or ordinary build log. If the field is missing or a download fails, record the task ID and failure, then report it without falling back to a watermarked link.

Download and validate the local file

Map the manifest filename to a stable MP4 basename under BlackStar_Videos. Download to a temporary file first so a failed or partial transfer does not look complete. Validate that the file exists and has nonzero length, then read the first 12 bytes and confirm the ASCII file-type marker ftyp at bytes 4–7. Only then move the file into its final path and record the byte count.

This is a container-level integrity check. It does not prove the video decodes fully, that the right shot was animated, or that the result is visually acceptable. If visual or audio review is part of the delivery contract, inspect the actual video with an appropriate playback tool and record those separate QA results.

Handoff record

The download ledger should include Clip, TaskID, TerminalStatus, LocalPath, Bytes, RefreshedWatermarkFreeURL, and Failure. The URL stays in the restricted CSV, not in the chat update. A concise handoff reports totals, validation status, and failures; it does not echo signed URLs or private provider IDs.

Observed delivery and reusable QA boundary

Observed: the 030–058 batch contained 30 video jobs because 056A and 056B were separate clips. Each task was refreshed, its indexed watermark-free URL was used, and each local MP4 was checked for nonzero size and the ftyp marker. The resulting download CSV retained the local paths, byte counts, statuses, and refreshed links.

Not established by that check: visual continuity, correct motion, no flicker, or audio quality. Keep those as explicit review steps rather than implying that a valid MP4 header proves creative quality.
