Orchestrating delegated media work

On this pagePartition work by ownershipMap dependencies before dispatchConcurrency and task ownershipCoordinator checklist

Partition work by ownership

Delegation helps when a large manifest can be split into independent row ranges. The coordinator should assign each worker an explicit, non-overlapping set of clip labels, the matching still directory, the approved prompt source, the permitted output path, and a results-ledger path. Special labels such as 056A and 056B are separate jobs and must remain separate even though they share the same number prefix.

Spawn a sub-agent only when the user or applicable task instructions authorize delegation. Give each child a self-contained assignment: exact row range, required inputs, allowed writes, generation or download rules, shared concurrency cap, and a required completion report. Do not delegate overlapping clip labels, and do not let a child silently expand its scope. The coordinator owns reconciliation and any cross-batch changes.

Assign each source shot to one owner and record which placements reuse it. In HARROW, placements 04 and 18 draw different trims from the same glass pilot take. A filename alone cannot identify the edit point.

Map dependencies before dispatch

The media pipeline has hard dependencies:

Treatment + still + manifest row
              ↓
        paid generation
              ↓
      terminal task result
              ↓
      indexed video work
              ↓
  refreshed delivery URL
              ↓
      local download + QA

Do not dispatch a dependent step before its prerequisite exists. Image-to-video jobs require the approved still to exist and match the manifest row. Downloads require a completed task and a usable video result at the original work index. If an upstream job fails, record the failure and do not invent a replacement source.

Concurrency and task ownership

In one recorded batch, the coordinator instructed that worker to keep at most three of its own paid generation tasks in flight. This was a worker-lane throughput rule, not an MCP protocol limit. The record does not establish the total number of simultaneous jobs across all workers, nor prove that a global provider cap was enforced. A per-worker cap cannot safely stand in for a shared global cap: three workers each following a local limit of three could collectively start nine jobs.

For a true global limit, the coordinator must maintain one shared slot ledger. A worker requests a reservation before submission; the coordinator grants it only when a shared slot and budget reservation are available. The worker performs a fresh account check immediately before its paid request, then reports acceptance or uncertainty. Keep an accepted or possibly accepted job in the shared active count until its task reaches a terminal state. Each worker’s account check is per request and is not a reservation against concurrent spending by other workers.

Within a worker’s ownership set, each clip was submitted once. The worker retained its generation ID and trace ID, then queried active generation IDs until they reached a terminal state. A 60-second poll timeout with RUNNING or QUEUING status kept the slot occupied; it did not authorize a duplicate request.

Coordinator checklist

Before dispatch, the coordinator should:

  • Confirm the manifest and approved stills are stable.
  • Partition clips into disjoint ranges and define exactly one owner per row.
  • Set the global maximum for in-flight paid tasks and enforce it through one shared slot ledger; record worker-local caps separately.
  • Require one durable result ledger per worker, with a coordinator-owned reconciliation file.
  • Define how failures, unknown task IDs, and expired result links are handed back.
  • Keep unwatermarked result URLs out of chat and ordinary logs.

In the HARROW v04 review, nine replacement takes map to specific editorial placements. Keep the placement number, source basename, task record and selected frame range together.
